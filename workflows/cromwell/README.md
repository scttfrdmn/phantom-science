# Phantom Science Cromwell Workflow

This directory contains a comprehensive WDL (Workflow Description Language) workflow for Cromwell that performs genomic analysis on FASTQ files generated by Phantom Science.

## Overview

The `phantom_analysis.wdl` workflow provides a complete pipeline for:

- **FASTQ Validation**: Quality and format compliance checking
- **Steganographic Analysis**: Fingerprint detection and analysis
- **Performance Metrics**: Throughput and processing analysis
- **Report Generation**: Comprehensive HTML and JSON reports

## Files

```
workflows/cromwell/
├── phantom_analysis.wdl    # Main WDL workflow definition
├── inputs.json            # Input parameters for the workflow
├── cromwell.conf          # Cromwell configuration
├── run_workflow.sh        # Execution script
└── README.md             # This documentation
```

## Quick Start

### Prerequisites

1. **Java 11+** - Required for Cromwell execution
2. **Cromwell** - Automatically downloaded by the cromwell wrapper script
3. **Basic Unix tools** - bash, curl, wget

### Run the Workflow

```bash
# Navigate to the cromwell workflow directory
cd workflows/cromwell

# Run the complete workflow
./run_workflow.sh

# Or run individual steps
./run_workflow.sh check     # Check dependencies
./run_workflow.sh validate  # Validate inputs
./run_workflow.sh clean     # Clean output directory
```

## Workflow Structure

### Input Parameters

The workflow accepts the following input parameters (configured in `inputs.json`):

```json
{
  "PhantomAnalysis.fastq_files": [
    "Sample_001_S1_L001_R1_001.fastq",
    "Sample_001_S1_L001_R2_001.fastq"
  ],
  "PhantomAnalysis.output_dir": "./cromwell_output",
  "PhantomAnalysis.customer_id": "phantom-science-demo",
  "PhantomAnalysis.analysis_type": "comprehensive",
  "PhantomAnalysis.min_quality_score": 20,
  "PhantomAnalysis.max_n_percentage": 5,
  "PhantomAnalysis.fingerprint_strategy": "balanced",
  "PhantomAnalysis.enable_steganography": true,
  "PhantomAnalysis.batch_size": 1000,
  "PhantomAnalysis.memory_limit_gb": 8.0,
  "PhantomAnalysis.cpu_cores": 4
}
```

### Workflow Tasks

#### 1. BatchValidation
- Validates FASTQ file format (4-line structure)
- Checks quality scores and N-percentage
- Generates validation report

#### 2. FingerprintAnalysis
- Analyzes steganographic content in quality scores
- Calculates embedding capacity
- Detects customer fingerprints

#### 3. PerformanceAnalysis
- Measures file processing throughput
- Calculates performance metrics
- Analyzes resource utilization

#### 4. GenerateReport
- Creates comprehensive HTML report
- Generates JSON summary
- Combines all analysis results

## Advanced Configuration

### Custom Input Files

Modify `inputs.json` to process your own FASTQ files:

```json
{
  "PhantomAnalysis.fastq_files": [
    "/path/to/your/sample1_R1.fastq",
    "/path/to/your/sample1_R2.fastq"
  ],
  "PhantomAnalysis.customer_id": "your-customer-id"
}
```

### Steganographic Strategies

Available fingerprint strategies:

- **conservative**: 1 bit per quality character (minimal detection risk)
- **balanced**: 2 bits per quality character (standard enterprise use)
- **aggressive**: 3 bits per quality character (maximum capacity)

### Docker Execution

To use Docker backend, modify the cromwell.conf:

```hocon
cromwell {
  backend {
    default = "Docker"
  }
}
```

## Performance Optimization

### Memory Configuration

Adjust memory limits based on your data:

```json
{
  "PhantomAnalysis.memory_limit_gb": 16.0,
  "PhantomAnalysis.cpu_cores": 8
}
```

### Call Caching

The workflow enables call caching for improved performance:

- Results are cached based on input parameters
- Subsequent runs with identical inputs reuse cached results
- Significantly reduces execution time for repeated analyses

## Troubleshooting

### Common Issues

1. **Java Version**: Ensure Java 11+ is installed
2. **Memory Issues**: Increase memory limits for large FASTQ files
3. **File Permissions**: Ensure FASTQ files are readable
4. **Disk Space**: Verify sufficient disk space for outputs

### Logs

Check these log files for debugging:

- `cromwell.log`: Cromwell execution logs
- `cromwell_output/execution_summary.txt`: Workflow summary
- `cromwell_output/metadata.json`: Detailed workflow metadata

### Validation

```bash

```
